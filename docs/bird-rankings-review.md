## Definitions and output contract

`dist/data/bird-rankings.json` is generated by `scripts/build-bird-rankings.mjs`
using the standard-library Python aggregator `scripts/lib/bird_rankings.py`.
There are no new dependencies or network requests in generation.

- Borough: records descending, original validated common name ascending. Stored
  `borough_rank` must match. Positions are unique; equal record counts are
  explicitly described as alphabetical ties, not different abundance.
- Least Recorded: records ascending, common name ascending. Eleven taxa have one
  record; Bohemian Waxwing is the first alphabetically, not the sole least-recorded taxon.
- Recent: observation dates from **29 September 2025 through 28 September 2026**,
  inclusive (end minus 364 days). End is the latest in-scope archive observation,
  not the computer clock. There are 3,496 records, 89 positive-record taxa and 44
  zero-record taxa. All 133 remain present. Zero-record taxa have null recent rank
  and null rank change, displayed as no recent records.
- Rising: all-time rank minus recent rank. Positive and negative values describe
  relative reporting positions, not population change. Order is change
  descending, recent records descending, then name; zero-record entries follow.
- Seasonal: month totals across all historical years and distinct years with at
  least one record for that month. Zero-count taxa remain present with no month
  rank. All twelve months sum back to each taxon's all-time records. Existing
  `movement_type` labels are joined from the validated calendar, not inferred.

`coverage.recordCount` counts only the public universe; source/excluded row counts
are separately named. `generatedAt` is the source seasonality release timestamp,
not a fabricated current generation time. The same input bytes produce identical
JSON. SHA-256 fingerprints identify the private archive/public CSV and published
calendar/metadata. No private paths, observations, identifiers, observers,
comments, locations or coordinates are emitted.

The shared offline/browser validator rejects unknown output fields, malformed
dates/counts, missing or duplicate taxa, unsupported classifications, ordering
errors, inconsistent recent/rising ranks, wrong monthly totals, unverified hotspot
output and mismatched coverage. The browser also requires strict READY metadata
and matching calendar/metadata fingerprints before showing any ranking content.
Failed, incomplete, missing or mismatched releases show an unavailable state.

## Generation and managed-refresh integration

The repository has no root `refresh.sh`. Its `upstream/refresh.sh` remains a
versioned Desktop-based prototype. The installed authoritative workflow belongs
to the separate private `birds-hf` repository at `3da699d`; this feature does not
replace or edit that repository or the managed installation.

Run the managed refresh as usual. After it produces a private READY bundle, use
its archive/public CSV and seasonality directory together:

```sh
npm ci
npm run build:archive-boards -- \
  /private/refresh/data/input/hf_ebird_records_final.csv \
  /private/refresh/data/output/birds_hf_public.csv \
  /private/refresh/seasonality \
  /private/releases/new-release
```

This downstream command copies the six seasonality outputs into a temporary
private directory, runs the existing full seasonality validator, generates the
new rankings and existing historical JSON, reconciles the two and renames the
complete directory to a **new, nonexisting** release destination. Failure removes
only the candidate directory. An existing release is never overwritten. There is
no copy to `dist`, Git operation or deployment. Keep candidates outside the board
repository. Review and approval are still required before promoting a complete
release's public aggregate files and matching seasonality outputs together.

For the feature's committed candidate, generation against the existing validated
seasonality files is explicit:

```sh
npm run build:rankings -- \
  /private/hf_ebird_records_final.csv /private/birds_hf_public.csv \
  dist/data dist/data/bird-rankings.json
```

This validates before atomically replacing only the ranking JSON. A failure
preserves its last known-good bytes. Source paths cannot be output destinations.
The importer and seasonality scripts are unchanged. Daily recent-observation
workflows do not invoke these historical builds. No GitHub Actions changes,
ingestion changes, identity changes or deployment-time gate are included.

## Interface and regression boundaries

The Historical category has a Bird Rankings bento tile opening an existing-style
accordion. Five native-select views, month selection, common/scientific search,
display sorting and 25-row pagination use semantic tables, labelled controls,
live result counts and visible keyboard focus. Canonical ranks remain unchanged
when sorting/searching. Narrow screens scroll the table within its labelled
region rather than overflowing the page. There is no existing internal species
detail route, so this feature does not invent one.

New JS/CSS assets are isolated. The service worker cache is versioned and new
ranking assets use network-first refresh with an offline cache fallback; fingerprint
verification still rejects mismatched releases. Existing feed and publication
workflows are unchanged. ADR-001 remains Accepted/operational and ADR-002 Proposed.
The pilot is not advanced by this work.

## Verification

Focused tests cover ranking/tie order, full-universe/hybrid preservation, the
inclusive recent window, zero records, positive/negative rank changes, monthly
records and distinct years, dates, identity/source failures, privacy exclusions,
deterministic replay, malformed public aggregates, metadata/fingerprint gating,
isolated release integration and last-known-good preservation. Historical hotspot
deduplication is not claimed: that view is deferred and nonempty hotspot output
is explicitly rejected.

The real-data candidate reconciles 133 taxa, 30,288 historical records and 3,496
recent-window records. All existing historical JSON and six seasonality files
remain byte-identical to the base. No production publication is authorized.
